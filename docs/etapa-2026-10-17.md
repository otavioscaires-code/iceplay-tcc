## 2. Comportamento verificado pela API

| Operação | Contrato de sucesso |
| --- | --- |
| `GET /api/geladeiras` | 200 e array JSON; lista vazia como `[]` |
| `GET /api/geladeiras/{id}` | 200 e os dados do ID solicitado |
| `POST /api/geladeiras` | 201, objeto criado e `Location` que permite consultá-lo |
| `PUT /api/geladeiras/{id}` | 200, campos editáveis atualizados e ID/criação preservados |
| `DELETE /api/geladeiras/{id}` | 204 sem corpo; novas operações sobre o ID excluído retornam 404 |

POST e PUT recebem `nome` e `localizacao` opcional. As respostas usam `id`, `nome`, `localizacao` e `criadoEmUtc`. O servidor controla ID e timestamp UTC; valores extras enviados pelo cliente não os alteram.

A suíte verifica nome obrigatório, limites de tamanho, espaços ASCII e Unicode, tipos incompatíveis, corpo vazio e JSON inválido. Cada rejeição 400 é seguida de consultas para confirmar que os cadastros não mudaram. Também verifica IDs inexistentes/inválidos, persistência após reiniciar o processo, contagem real pela saúde e falha de banco com resposta genérica.

## 5. Executar e reproduzir

Para iniciar o sistema neste computador, em PowerShell 7.5 ou posterior:

```powershell
Set-Location C:\Users\otavi\Downloads\iceplay
.\scripts\setup.ps1
.\scripts\run.ps1
```

Abra [ICEPLAY local](http://localhost:5080/) e acesse **Geladeiras**. A execução normal usa `src/Iceplay.Api/data/iceplay.db`. A saúde está em [GET /api/health](http://localhost:5080/api/health) e consulta de fato a tabela; contagem zero pode representar banco saudável e vazio.

Para repetir as verificações isoladas, encerre a aplicação antes de compilar e execute:

```powershell
.\scripts\verify.ps1 -EvidenceDirectory docs/evidencias/2026-10-17/base
.\scripts\verify-geladeiras.ps1 -EvidenceDirectory docs/evidencias/2026-10-17
```

Para repetir a inspeção SQLite com o Python disponível:

```powershell
$teste = Get-Content .\docs\evidencias\2026-10-17\base\smoke-latest.json -Raw | ConvertFrom-Json -DateKind String
python .\scripts\verify-database.py $teste.isolatedDatabase
```

Esses comandos reproduzem os testes, mas substituem os relatórios da pasta indicada. Para manter também esta rodada, escolha outra pasta e use seu relatório da base ao executar a inspeção SQLite. Os bancos de teste são criados em `.tools/verification`; os scripts encerram somente seus próprios processos.

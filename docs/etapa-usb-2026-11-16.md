# Primeiro reconhecimento USB do ESP32 — 16/11/2026

## Resultado real

O usuário apresentou fotos dos dois lados de uma placa identificada como **ESP32 DEVKITV1**, com conversor **CP2102**, e relatou LED vermelho após conectar o USB. As fotos identificam a peça; não comprovam execução do firmware ICEPLAY. O modelo exato do processador ainda não foi consultado pelo carregador serial.

O Windows detectou inicialmente `CP2102 USB to UART Bridge Controller`, sem classe/porta COM, problema **28** e sem INF associado. O código 28 corresponde à ausência de driver, conforme a [Microsoft](https://support.microsoft.com/en-us/windows/hardware/drivers/error-codes-in-device-manager-in-windows). Esse estado foi observado nas consultas executadas antes da instalação; não foi produzido um arquivo JSON automático daquela consulta inicial.

Após autorização explícita do usuário (“Pode instalar”), foi instalado o driver **Silicon Laboratories Inc. 11.5.0.417**, obtido no [Microsoft Update Catalog](https://www.catalog.update.microsoft.com/ScopedViewInline.aspx?updateid=34213758-173c-47ec-951d-16b2c9463881). O CAB contém o INF com `USB\VID_10C4&PID_EA60`, seção AMD64 para Windows 10 a partir do build 17134, compatível com o Windows 10 Pro x64 build 19045 deste computador. O catálogo `silabser.cat` apresentou assinatura `Valid`, de **Microsoft Windows Hardware Compatibility Publisher**. A instalação por PnPUtil terminou com código **0**.

Verificação posterior, em **16/11/2026 às 16:26:05 UTC**:

| Propriedade consultada | Resultado |
| --- | --- |
| Dispositivo | Silicon Labs CP210x USB to UART Bridge (COM3) |
| Classe | Ports |
| Porta | COM3 |
| Status | OK |
| Código de problema | 0 |
| Versão do driver | 11.5.0.417 |
| INF publicado neste Windows | oem15.inf |

Isso comprova o reconhecimento USB/serial pelo Windows. Não foi feita consulta ao processador, gravação de firmware, leitura de sensores ou envio físico à API. **F01 permanece parcial** no [protocolo de ensaio](hardware/protocolo-ensaio.md). COM3 e o nome publicado do INF são locais e podem mudar em outra instalação.

## Evidências e comandos

- [Instalação, origem, hash e assinatura](evidencias/2026-11-16-usb-cp2102/driver-instalacao.json).
- [Consulta posterior do dispositivo e da COM](evidencias/2026-11-16-usb-cp2102/verificacao-usb.json).
- Pacote, manifesto e registros locais adicionais em `.tools/drivers/cp210x-microsoft-20261116-132450`, ignorado pelo Git. Não publicar binários do driver ou copiar configurações privadas junto das evidências.

Foram executadas consultas `Get-PnpDevice -PresentOnly`, `Get-PnpDeviceProperty` e `Get-CimInstance Win32_SerialPort`; consulta de sistema operacional; download HTTPS do CAB; extração com `expand.exe -F:*`; inspeção do INF; `Get-FileHash -Algorithm SHA256` e `Get-AuthenticodeSignature` do catálogo.

A instalação autorizada usou `Start-Process`, elevado pelo mecanismo normal do Windows, com `C:/Windows/System32/pnputil.exe` e os argumentos `/add-driver "<caminho local verificado>/silabser.inf" /install`. O processo retornou 0; sua saída de console não foi capturada. O resultado foi confirmado pelas consultas posteriores, registradas nos JSONs. Não houve remoção de drivers, reinício forçado, alteração de proteção do Windows ou gravação na placa.

As tentativas de download direto do ZIP no domínio da Silicon Labs, por `Invoke-WebRequest` e `curl.exe`, retornaram **HTTP 403**. O controle de navegador também estava indisponível nesta conversa. A alternativa foi o catálogo oficial Microsoft, com compatibilidade e assinatura verificadas; nenhuma instalação foi iniciada a partir dos downloads recusados.
